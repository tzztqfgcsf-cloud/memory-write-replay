# Completed test-lane resource accounting (2026-09-28 cutoff)

This is a read-only accounting of the six completed **main test** lanes: original Gemini 2.5 Flash, Llama 3.1 8B, Qwen3 14B, and the later Gemini 3.8 Flash, 3.5 Flash Lite, and 3.1 Pro Preview lanes. Each lane has 144 case-repeat units and 864 saved physical response records. The corresponding original `outputs.jsonl` files, candidate IDs, and the saved E/E_text outputs are the only inputs. The Qwen first analysis was checked for completion; scores were not read into or changed by this accounting. Probe, challenge, transfer, and still-running 31B/32B collections are excluded.

`physical.csv` counts each saved response `call_id` once per model. Across the six lanes there are **5,184 physical attempts**, of which **5,162 have status OK** and **22 have a recorded provider failure** (5 Gemini 2.5, 8 Gemini 3.5 Lite, 9 Gemini 3.1 Pro). Each physical lane has 864 records. Failed attempts remain in the attempt and latency denominators. Their missing token usage is unmeasured, not zero or free.

`logical_conditions.csv` uses unique `upstream_call_ids` within each full arm and model. D uses 144 calls; G, B, C, R, CR, E, and **E_text each reference 288**; SR1 references 432. B, C, R, and CR reference **the same two candidate calls per case-repeat**, verified as identical sets. E and E_text reuse those same B calls and add zero inference calls. The complete E_text policy has 144 case-repeat units per model: its H-exposed units were executed on saved proposals, while non-H units are analytically identical to B. The saved outside-H manifest verifies this partition for the first five lanes; the Qwen saved-output receipt verifies its H and outside-H counts. Even models with zero H-exposed units retain all 288 B calls in the full E_text policy.

`e_text_h_subset.csv` separately shows only the observed H-exposed rows and the source calls referenced by those rows. Its row counts are 11, 2, 10, 0, 5, and 0 for Gemini 2.5, Llama, Qwen14, Gemini 3.8, Gemini 3.5 Lite, and Gemini 3.1 Pro respectively. This subset is a diagnostic denominator, **not** the full-policy resource denominator. Six mechanism-fixture rows without a model alias or upstream call IDs in the E_text source are excluded. Logical-arm token and latency sums overlap; **do not sum them across arms** or add E/E_text to the 864 physical attempts.

All token sums are `sum_measured` with a companion `measured_calls` for that exact field. Empty sums are null. Input, output, and total tokens are present on 5,162/5,184 physical records; reasoning tokens on 3,434/5,184; cached tokens on 56/5,184; latency on 5,184/5,184. The measured physical totals are 11,588,588 input, 956,763 output, 30,074 separately reported reasoning, and 12,575,425 total tokens. **Total already includes reported reasoning** where present; do not add the reasoning column to total. Vertex normalization maps `promptTokenCount`, `candidatesTokenCount`, `thoughtsTokenCount`, `totalTokenCount`, and `cachedContentTokenCount`; missing thought counts on successful Vertex responses normalize to zero. The local provider uses its tokenizer's input count and generated-token count, reports total as their sum, and leaves reasoning and cache fields null. Thus local null reasoning is not evidence of zero compute. The Qwen run disabled thinking in its generation settings. Cached tokens, when reported, are a subset of input accounting, not an additional amount to add.

Latency is the **sum of per-call recorded elapsed seconds**, including failures: 52,021.9724 seconds across six models. It is not wall-clock elapsed time, critical-path latency, GPU-hours, or a hardware-normalized benchmark. The lanes used different models, settings, and execution backends. Matching the number of proposal calls therefore does **not** establish compute, token, time, or monetary cost matching. E_text's simple literal rule differs in code complexity, but this experiment does not establish lower model tokens or inference cost for that rule: all candidate proposal calls are shared with B, and policy execution time was not separately benchmarked. No price or charge is inferred. Source file digests and response-path/hash manifest digests are in `INPUT_HASHES.json`; the generator checks every physical ID against original output references and verifies B/C and E/E_text reuse before writing these tables.
