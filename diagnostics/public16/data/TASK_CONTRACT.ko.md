# MultiWOZ 원문 전이 개발 계약 v1

이 자료는 **기존 방법의 개발 진단**이다. 공개 영어 문어 대화가 출처이며, 시니어 음성·ASR 혼동·개인기억 효능의 독립 확인이 아니다. 원문은 한 가지뿐이고 인위적인 전사 대안은 만들지 않는다. `candidate_texts`에는 같은 원문 `c1` 한 개만 있다. 모든 후보의 공통 지지를 묻는 기존 C 게이트의 복수 전사 대비 효과를 이 자료로 시험할 수 없다.

`public_packets.json`은 각 사례의 대상 턴 이전 **모든 실제 대화 턴**, 대상 영어 user 발화 한 개, 그리고 대상 직전 system turn의 **원래 MultiWOZ dialogue-state 주석** 중 사전에 지정한 domain.part.slot만 담는다. 대상 뒤 system 발화와 그때의 상태 주석, 사례 분류와 작성자 예상은 `provisional_reference.json`에만 있다. 원자료의 철자·띄어쓰기·시각 표기를 고치지 않는다.

원자료에는 개인기억 DB도, 사용자에게서 받은 영속저장 동의도 없다. 상태편집 과업을 실행한다면 **실험용 임시 dialogue-state의 변경 제안을 허용한다고 가정**할 뿐이다. 이는 실제 서비스 사용자의 동의나 실제 외부 예약 수정의 증거가 아니다. 모델 프롬프트와 보고서 모두 이 조건을 명시하고, 실제 예약 완료·취소·금액 청구 등을 출력에서 확정하지 않게 해야 한다. 상태 이전값이 `not mentioned` 등 비어 있음 표지이면 기존 사실로 CORRECT하지 않는다.

허용할 원자 관계는 `relation_vocabulary.json`의 정확한 `domain.part.slot`뿐이다. `train.semi.destination`을 `travel_destination` 같은 개인경험 관계로 바꾸지 않는다. `subject`는 한 대화의 해당 domain.part 과업을 가리키는 구성 ID이며 원자료의 별도 인물 식별자가 아니다. 원문에 벽시계 시각은 없고 대화 턴 순서만 있다. 과거 주장을 후속 변화 시점까지 참으로 보존할지, 처음부터 잘못된 주장인지 구분한다.

16개에는 source-reader 잠정 정정 10, 계획/대안 변화 3, 조수 오해·질문·주석 불일치 3을 포함한다. `PMUL1690`은 원문상 Ely→Cambridge 정정이 있으나 이후 데이터 주석이 Ely인 **불일치 사례**로, 해당 슬롯의 dataset-label 점수에서 제외/미결로 둔다. 모든 예상 행동은 작성자 AI provisional이며 독립 사람 gold가 아니다. 모델 출력 또는 점수를 보기 전에 적격성, 복수 허용 행동, 정답 비교 범위와 중단 조건을 동결해야 한다.

계획 물리 호출 상한은 16사례 × 6단계 × 2모델 = **192 attempts**, retry 0이다. 비교 예정 모델은 Gemini 2.5 Flash와 Qwen3 32B이고 정확한 ID·가중치·sampling·프롬프트·평가·호출 중단 조건은 본체가 실제 실행 전에 별도로 동결한다. 이 폴더의 모델 호출·학습·유료 실험은 0이다.
